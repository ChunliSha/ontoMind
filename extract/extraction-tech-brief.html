OntoMind · Technical Brief

本体约束下的 LLM
实例抽取技术说明

面向已有 Schema（类 / 对象属性 / 数据属性），从非结构化业务文档中抽取可落地到 RDF 的 ABox 实例与关系。 实现入口：extract/populate_ontology.py。

问题定位：TBox 已定 → 抽 ABox，而非从零归纳 Schema
技术路线：Schema-grounded LLM + 结构化输出 + 对齐落库
栈：semantica · OpenAI-compatible LLM · rdflib / TTL
样例域：电力缺陷检修（变电站 / 设备 / 缺陷 / 工单）

1. 端到端流水线

01 读 Schema OntologyIngestor
类 / 对象属性 / 数据属性
02 读文档 FileIngestor
样例 MD → 纯文本
03 LLM 抽取 NER → 关系 → 三元组
类型受 Schema 约束
04 对齐 别名归一 · mint IRI
对象边 / 字面量分流
05 合并导出 TBox ∪ ABox
→ populated.ttl

与主站「Schema 归纳」互补：归纳产出骨架；本流水线在骨架上填充个体与关系。

2. 实体抽取：核心技术细节

不是经典序列标注 NER

采用 LLM 生成式抽取 + JSON Schema 约束，类型体系来自领域本体，而不是 PERSON / ORG / GPE。

  • methods=["llm"]，关闭通用标准类型
  • entity_types = 本体类（含 LocalName + 中文 label）
  • confidence_threshold=0.7

结构化输出保障

通过 instructor + Pydantic（EntityOut）做 typed generation；自定义 API Base（如 OpenLab）走 JSON Mode，避免第三方网关不支持 Tools。

  • 强制扁平列表：{"entities":[...]}
  • 字段：text / label / confidence
  • 校验失败带错误信息最多重试 3 次

Prompt 契约（语义摘要）

Extract named entities from the provided text.
Return JSON: { "entities": [ { "text", "label", "confidence" }, ... ] }

Preferred entity types: Transformer (变压器), Defect (缺陷), ...
- Prefer types from the list; close synonyms allowed
- Flat list only; do not group by type
- Extract ONLY from the source text below

Text:
<document>

置信度重打分（过阈值前）

final = 0.5 × model_confidence + 0.5 × max(label_similarity, content↔type_similarity)
保留条件：final ≥ 0.7

模型自评分会与「类型是否贴近 Schema」混合。类型漂移会被拉低；贴合本体的 mention 更容易过线。

3. 从 mention 到 RDF 实例：第二道闸

① 别名归一

normalize_term 将 Transformer / 变压器 / Transformer (变压器) 映射到 Schema local name；对不齐则丢弃。

② IRI 铸造

#{Class}_{slug(mention)} 例：Transformer_1号主变压器 命名空间固定为电力本体 NS。

③ 跨文档去重

同 IRI 只保留首次；关系端点用 mention 字符串包含匹配解析实例，保证边能挂上。

两层过滤：LLM 候选 →（置信度 + Schema 相似度）→ 本体类归一 → ABox 实例。 因此「NER 实体数」通常大于「对齐后实例数」，属预期行为。

4. 关系与三元组（实体之后）

阶段 输入 约束 产出
RelationExtractor 文本 + 已识别实体 对象属性类型列表；阈值 0.6 实体间对象关系
TripletExtractor 文本 + 实体 + 关系 对象属性 ∪ 数据属性 (s, p, o) 三元组；再 validate
map_graph 分流 关系 + 三元组 谓词别名归一 对象边 → 实例链；数据属性 → Literal（date 后缀用 xsd:date）

实体质量直接决定边能否对齐：端点解析失败的关系会被静默丢弃。

5. 与经典 NER / 开放域 IE 的对比

维度 本方案（Schema-grounded LLM） 经典 spaCy / 序列标注
类型体系 领域本体类（封闭 + 软同义） 通用标签 PERSON/ORG/GPE…
适配成本 换 TTL 即可换域，少训练 需标注数据或迁移学习
可落地性 对齐后直接进 RDF ABox 需额外映射层
风险 幻觉 mention、类型漂移、同名合并粗 领域外召回差、类型不匹配本体
位置信息 LLM 路径常缺可靠 offset 有稳定字符跨度

6. 工程要点（给评审的结论）

设计选择

  • 用 Schema 当约束，不做开放域百科抽取
  • 结构化输出优先于自由文本后解析
  • TBox 原样保留，输出 = Schema ∪ 实例
  • 对象属性 / 数据属性显式分流

已知边界

  • 跨文档实体合并偏启发式（字符串包含）
  • md 摄入可能告警但可读文本
  • 长文依赖 chunk；网关需 OpenAI 兼容
  • 对齐失败静默丢弃，需靠摘要日志观察召回
一句话结论：本抽取不是「找专名」，而是在给定电力检修本体类型集合中，用 LLM 结构化生成候选提及，经置信度与 Schema 对齐双重过滤后，铸造成可合并进 TTL 的 RDF 个体与关系。
